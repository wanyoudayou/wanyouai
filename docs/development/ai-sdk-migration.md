# AI SDK 接入与维护

本文规定 AI SDK 接入边界、依赖升级与回退检查。产品行为以 [AI 工程规则](ai-settings-plan.md)、[Embedding 规格](embedding-implementation.md)和 [Skill 契约](../contracts/skills.md)为准。

## 1. 目标与选择

将协议适配、流式事件解析和通用调用机制迁入 Vercel AI SDK，降低开源项目维护者处理供应商接口变化、SDK 升级和错误诊断的负担。迁移价值同时考察维护者和部署者，不以新增前台功能作为前提，也不单按删掉多少行代码判断收益。

应用采用 AI SDK Core 与必要的直接供应商适配器。沿用 Next.js、Vercel、Supabase、已有模型账户和后台配置，不新增常驻服务、网关账户、队列服务或必填环境变量。

| 方案 | 维护与部署影响 | 本次选择 |
|---|---|---|
| AI SDK Core＋直接适配器 | 通用协议由上游维护；部署仍是现有网站；增加锁定版本的 npm 依赖 | 已采用 |
| AI Gateway | 可以集中部分供应商接入，但增加账户、计费与服务依赖；能力和直连未必等价 | 不作为安装前提，后续有明确收益再单独评估 |
| OpenAI Agents SDK | 可接管 Agent 循环和委派，但与 AI SDK 的部分职责重叠 | 本轮只选择一套调用基础，不叠加 |
| Mastra／LangGraph | 适用于多步骤持久工作流；还需整合状态存储、权限、部署与恢复 | 出现具体长任务后再评估，暂不迁移现有索引任务 |
| LibreChat／LobeHub 整体环境 | 更换整套产品需重新整合身份、会话、模型配置与内容权限 | 借鉴交互与模块设计，不把整套产品作为网站附属服务 |

官方依据：AI SDK 的 [Core 与 UI 定位](https://ai-sdk.dev/docs/introduction)、[直接兼容接口与自定义 fetch](https://ai-sdk.dev/providers/openai-compatible-providers)、[Anthropic 适配器](https://ai-sdk.dev/providers/ai-sdk-providers/anthropic)、[DeepSeek 直接适配与网关差异](https://ai-sdk.dev/providers/ai-sdk-providers/deepseek)。

## 2. 可替换范围与业务权威

| 当前入口 | 职责 | 去留 |
|---|---|---|
| `src/lib/ai/generation.ts` | 保持 `generate` 的调用签名；内部使用 SDK 生成与流式接口，检查结束状态并映射项目错误 | 删除自写的三套通用协议解析，保留薄边界 |
| `src/lib/ai/embedding.ts` | 内部使用 SDK 向量接口；保留模型、顺序、数量、维度及数值校验 | 删除重复接口适配，不删除业务数据校验 |
| `src/lib/ai/transport.ts` | 通过自定义 fetch 接入 SDK，仍执行固定目标、DNS 检查与连接绑定、TLS、期限和字节限制 | 保留一个安全网络实现，不复制第二套 |
| `src/lib/ai/connections.ts` | 将后台连接映射为明确的 provider／协议；凭据显式传入 | 保留连接权威和受信目标清单 |
| `src/lib/ai/call-control.ts` | 管理预算预留、派发与结果状态；网络调用与记账一致 | 保留，不交由 SDK 取代 |
| 分身、知识库、自定义页面 | 继续组织各自任务指令、检索、权限、缓存、净化和保存 | 复用现有服务，不改变业务状态机 |
| `src/lib/skills/runner.ts` | 第一轮保持受限 JSON 读文件流程，底层生成改用共享 SDK | 原生工具调用作为后续独立批次 |

现有调用集中经过 `generate` 和 `embed`，这是迁移成本可控的依据。各页面无需逐个接入 SDK，客户端也不接触供应商凭据。

目标结构是：业务服务 → 统一调用边界 → AI SDK／provider → 现有安全出站层 → 指定供应商。权限、任务指令与账本始终在业务侧生效。

## 3. 依赖升级与兼容性验证

在独立开发分支、合成请求和受控传输替身中验证，不发起真实模型调用、不写远端数据、不安装第二套运行环境。

### 版本与许可证

依赖采用 npm 稳定版本并锁定精确版本。当前接入版本为 `ai@7.0.154`、`@ai-sdk/openai@4.0.103`、`@ai-sdk/openai-compatible@3.0.79`、`@ai-sdk/anthropic@4.0.89`；均声明 Node.js ≥22、Apache-2.0，并需要兼容版本的 Zod。升级时重新确认包之间的依赖、Zod 版本、许可证和安全公告，不混用主版本或采用 canary／beta 标签。

第一轮不引入 `@ai-sdk/react`，避免同时更换前端消息协议。Zod 仅用于 SDK 所需的校验，不替换已有 JSON Schema 契约体系。

### 协议与请求映射

| 现有连接 | 候选接入路径 | 必须验证 |
|---|---|---|
| OpenAI Chat | OpenAI 适配器的显式 chat 接口 | 不因默认模型工厂切换为 Responses |
| OpenAI Responses | OpenAI 适配器的显式 responses 接口 | `store: false`、完整结束事件、取消、用量 |
| DeepSeek Chat／Responses | 按原协议分别验证兼容适配器或 OpenAI 适配器；只有确实减少专用处理时才增加 DeepSeek 包 | 保留当前模型 ID、非思考设置和原接口路径；不自动改模型或协议 |
| 硅基流动 Chat | OpenAI-compatible 适配器 | 流式用量、结束状态、错误和参数兼容 |
| 硅基流动 Embeddings | OpenAI-compatible 的 embedding 接口 | `BAAI/bge-m3`、float、原始响应校验和一次批次一次请求 |
| Anthropic Messages | Anthropic 适配器 | 指令与对话分离、文本／思考区分、终止状态与用量 |

兼容性检查覆盖现有所有受支持协议。不能以一个供应商能回复文本，就认定整个迁移通过。SDK 默认模型、隐式环境变量或网关不得覆盖后台保存的连接。

### 三项决策条件

1. 每种协议都能使用相同的受控 fetch 边界，无隐藏外连、自动重定向或额外资源下载。
2. 结束状态、用量、取消和异常可以准确映射，保留现有安全回归的意义。
3. 可以移除重复的协议实现；新增桥接代码没有重新实现同样的解析器，也不要求部署者承担新的配置步骤。

任一条件不成立，定位到具体协议或 SDK 限制后评估调整；不为了换框架而削弱权限、保留两套完整生产实现或长期维护上游 fork。

## 4. 生成调用

保留 `generate(connection, messages, options)`，先替换该入口内部实现。分身回答、连接检查、页面生成、诊断问题生成、预演和 Skill 使用同一个入口；不在路由中分别调用 provider。

- 显式指定 provider、模型、协议、凭据、`maxRetries: 0`、输出上限与 AbortSignal。不使用默认网关、自动模型切换、自动输出修复或续写。
- 新增薄 fetch 桥接：规范化 SDK 的 URL／Request 输入，校验方法、origin、路径和请求容量；由现有网络层重新建立受信鉴权，不转发任意凭据或请求头。保留 SDK 必需且经过允许清单审查的协议头。
- 保留全部 DNS 地址检查、固定连接 IP、TLS hostname 校验、禁重定向及响应容量上限。禁止 URL 型文件输入和 SDK 自动下载外部资源，现阶段只接收项目构造的文本消息。
- 流式读取只向现有回调传文本增量；推理、工具事件与供应商原始错误不作为正文。只有确认正常结束并保存结果后才显示完成；部分输出不得冒充完成回答。
- SDK 警告和错误归一为项目可诊断代码，原始请求、响应、密钥、包正文和付费内容不得进入日志。默认不启用外部遥测、DevTools 数据上传或正文追踪。
- 一次普通生成只允许一个模型步骤、一次网络派发；调用前后仍经过现有预算与结果记账。流对象创建成功不等于调用已完成，须等流结束后记录成功。

SDK 的 [重试与期限配置](https://ai-sdk.dev/docs/ai-sdk-core/settings)不能照搬默认值。离线测试要统计实际请求数，验证流中断、429、5xx 和输出错误都不会触发未授权的再次计费请求。

完成后移除旧 SSE／三协议解析器及仅服务旧实现的测试细节。保留协议、安全和业务结果测试，不让测试要求继续保留旧函数结构。

## 5. 向量调用

复用同一连接工厂、安全出站和错误映射，通过 SDK 的原始响应信息执行现有向量校验。官方 [Embedding 接口](https://ai-sdk.dev/docs/ai-sdk-core/embeddings)提供重试、并行和响应信息，但具体字段仍须对锁定版本检查。

- 保留 BGE-M3、1024 维、float、原输入和顺序、分片与预处理版本，不调整相关性阈值。
- 保留每批最多 16 条、每条最多 2048 UTF-8 字节与现有期限。关闭重试、缓存、隐式去重、输入截断与无界并行；验证一个应用批次不会在 SDK 中被拆成多次未经独立记账的请求。
- 在 SDK 归一化丢失信息之前，核对原响应模型、`data[].index` 唯一性、输入输出数量、有限 float32、非零向量和容量。不得只校验归一化后的数字数组。
- 现有索引代际、租约、来源版本、权限过滤及后台继续／恢复流程不迁移到框架存储。切换前后用相同的合成请求和响应夹具核验向量顺序及结果一致。

仅替换客户端且上述语义保持一致时，不需要新 SQL、全库重建或重新发送文章正文。真实供应商若显示行为改变，停止该连接切换，另按现有模型变更规则处理，不混用新旧向量。

## 6. 部署与维护

1. 运行 contracts、docs:check、lint、typecheck、build，以及 AI、分身、Skill 和受影响后台／浏览器回归。现有 CI 继续执行完整必需作业。
2. 在现有测试环境部署同一候选，沿用变量、凭据和数据库。后台选择连接、开关、知识库与原会话照常可用。
3. 经必要的单独授权，用少量合成文本检查真实生成、流式、向量和取消；记录次数与实际用量。对没有可用账户的协议如实列出未完成验证，不能声称真实兼容全通过。
4. 完成匿名／未购／订阅／已购／站主权限矩阵，付费正文和私有包不进入未授权响应、上下文或追踪；页面生成仍经过原有净化与手动发布。
5. 更新 AI 工程规则、测试说明、架构图与第三方告知。部署指南只写部署者需要执行的变化；若无需操作，明确应用升级即可，安装入口不增加 SDK 专属步骤。
6. 删除迁移时的旧生产实现和临时切换选项，产出源码包与校验。回退通过前一兼容应用工件执行，不要求站主维护永久的“新／旧 AI 引擎”配置。

不做双引擎在线影子请求，避免同一操作重复计费或扩大数据发送范围。离线夹具可以同时比较；线上每次请求只使用一条实现路径。

## 7. 后续独立批次：Skill 原生工具调用

完成前四批后，再决定是否把受限 JSON 循环迁移为 SDK 原生工具。第一轮维护收益不依赖这项改造。

唯一工具仍是读取服务端绑定的当前 Skill 版本内允许的文本。用户、版本与访问权不能由模型参数覆盖；脚本执行、任意网络、数据库和文件写入不开放。宿主固定规则、包指令与用户输入继续分层。

改造前须确认现有可用模型对原生工具的兼容性；不会因连接检查能聊天便宣称工具可用。兼容性不足时不自动在同一轮换成另一个模型、协议或 JSON 引擎重跑，也不影响已完成的生成层迁移。

工具执行前后重新验权；整轮最多 3 次模型请求、6 次文本读取、45 秒和现有总容量。每个真实模型子调用单独进账，不能只对外层循环记一次费用；并行工具不能绕过共享的原子计数。对话中途权限失效、未知工具、跨包路径和结果过大均停止。

历史会话继续由服务端提供，复用已保存的用户问题和最终回答，不信任客户端提交的系统／工具历史。SDK 工具事件仅作为当前执行的受控过程数据；若要持久保存工具事件、改变会话结构或前端流协议，须另列契约与数据变更，不能夹带到调用层迁移。

## 8. 如何判断维护收益

交付时提供迁移前后对照，不以“接入了框架”作为成功标准：

| 维度 | 验收依据 |
|---|---|
| 部署负担 | 必填变量、平台账户、SQL 操作、后台配置步骤、常驻服务均不增加 |
| 自维护范围 | 通用协议和流式解析交给上游；项目只维护配置映射、安全、权限与业务校验 |
| 日常排错 | 连接／鉴权／限额／超时／协议／业务校验错误可区分；用户内容和凭据不随错误输出 |
| 升级负担 | 一个锁文件、精确版本、可重复协议夹具、升级记录；不修改 node_modules 或长期 fork |
| 行为与资源 | 权限、账本、取消与既有内容不退化；测试请求次数不增加；比较构建体积、冷启动和响应耗时 |
| 回退与数据 | 无数据转换，前一兼容工件可回退；内容、订单、权益、包和向量不因应用回退丢失 |

SDK 接入不改变部署变量、SQL 结构或既有模型配置。依赖升级仍须分别记录离线回归、真实供应商和部署验证；前者不代替后两者。Skill 原生工具调用是独立变更，当前保留受限 JSON 执行流程。
