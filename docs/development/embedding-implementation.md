# Embedding 接入与知识库索引实施规格

本文描述 AI 设置与知识库的向量实现及安全边界。统一后台入口为 `/admin/ai`；分步交互与增量候选见 [AI 设置操作流程](ai-settings-plan.md#8-连接检查与索引操作流程)，实际部署与真实供应商结果见[发布状态](release-status.md)。

## 1. 首个落实的接入组合

首个兼容性验证目标选定为**硅基流动中国区的 `BAAI/bge-m3` 稠密向量接口**。生成可保留 DeepSeek 官方连接；若希望只维护一个供应商账户与 Key，可将生成也配置为硅基流动提供的生成模型，显式复用该平台凭据。两者都在 AI 设置页管理，不要求站主分别维护环境层和数据库配置。

| 项目 | 固定规格 | 依据与限制 |
|---|---|---|
| 接口根地址 | `https://api.siliconflow.cn/v1` | [官方 Embeddings API](https://api-docs.siliconflow.cn/docs/api/embeddings-post) |
| 请求 | `POST /embeddings`，Bearer 鉴权 | OpenAI 兼容 Embeddings 请求，不是聊天请求 |
| 模型 | `BAAI/bge-m3` | 官方接口明确列出；账户是否可用仍须实测 |
| 输出 | `encoding_format: "float"`，原生 1024 维 | [BAAI 模型卡](https://huggingface.co/BAAI/bge-m3)列出维度及多语言能力；与现有 `vector(1024)` 一致 |
| 输入长度 | 模型上限 8192 tokens | 不是 8192 个汉字；应用使用更短片段，不把全文塞入一次请求 |
| `dimensions` 参数 | 不发送 | 硅基流动文档中该参数仅适用于 Qwen 系列，不能用它强行改变 BGE 维度 |
| 检索方式 | 稠密向量＋余弦相似度 | 本次不增加稀疏向量、ColBERT 或 Reranker 服务 |
| 模型可用性 | `GET /models?sub_type=embedding` 后实际调用 | [模型列表 API](https://docs.siliconflow.cn/docs/api/models-get)只能证明列出，不能代替调用成功 |

固定请求形状如下，Key 只由受信服务端加入请求头：

```json
{
  "model": "BAAI/bge-m3",
  "input": ["要索引的完整片段", "另一个完整片段"],
  "encoding_format": "float"
}
```

响应须按 `data[].index` 恢复输入顺序；检查模型、数量、索引唯一性、1024 维、有限且可表示为 float32 的数值、非零向量及响应字节上限。任一项失败，整批不得写入。不能只检查 HTTP 200 或数组长度。

硅基流动[官方接入示例](https://docs.siliconflow.cn/docs/usercases/use-siliconcloud-in-deepstudent)展示同一平台 Key 配置生成与 bge-m3。这是“可显式复用凭据”的依据；不是 DeepSeek 官方 Key 可用于硅基流动的依据。生成模型从该账户的 `sub_type=chat` 列表选择，并另做一次最小生成检查，不固定引用可能已下线的旧型号。

[DeepSeek 官方 API 文档](https://api-docs.deepseek.com/api/list-models/)没有提供本方案可据以接入的 Embeddings 接口，因此不把“OpenAI 兼容”推导为具有向量能力。保留 DeepSeek 官方生成时，Embedding 使用独立硅基流动连接；两种方案不自动互换 Key、不自动更换供应商。

本次不迁移到另一向量数据库，不自建 GPU 服务，不要求额外安装 Python。模型服务费用与账户限额以站主使用时的供应商控制台为准；不承诺免费、无限或自动扩容。

## 2. 可执行的真实接口检查

仓库根目录、Node.js 22 或更高版本：

```bash
npm run embedding:check
```

这只显示说明，不读取 `.env.local`，不联网。实际验证由站主在本机交互终端显式执行：

```bash
npm run embedding:check -- --live
```

终端随后要求输入**硅基流动** Key，输入不回显，不把 Key 写入 shell 命令、文件或报告。不要输入 DeepSeek、Supabase 或其他平台的 Key。该操作最多发出 3 次 HTTP 请求：一次模型列表、两次 Embeddings，共 7 条固定合成文本，可能计费；每个请求含响应读取最多 15 秒，不自动重试，不读取实际文章、连接 Supabase、调用生成模型或启用分身。

工具验证：账户列出目标模型、批量输入、响应顺序、向量格式、同输入重复一致性，以及三组中英文问题是否优先命中对应示例。只输出固定模型标识、检查结果和数值摘要；失败只输出本地错误代码与必要 HTTP 状态，不输出供应商原始响应或凭据。`REPEAT_INCONSISTENT` 的 0.99 是该冒烟检查的一致性门槛，不是知识库相关性门槛。

| 失败代码 | 处理 |
|---|---|
| `MODEL_NOT_LISTED` / HTTP 403、404 | 核对账户权限与模型是否仍提供；不静默切到 Pro 或其他模型 |
| HTTP 401 | 在硅基流动核对 Key，不反复发送其他平台 Key |
| HTTP 429、503 / `DEADLINE_OR_CANCELLED` | 停止本次检查，后台保持未验证；不宣称永久不可用 |
| `MODEL_MISMATCH` / `INVALID_VECTOR_*` / `VECTOR_COUNT_MISMATCH` | 兼容性未通过，禁止写入索引 |
| `SEMANTIC_SMOKE_FAILED` / `REPEAT_INCONSISTENT` | 格式通过也不算可用，核查模型与服务输出 |

离线协议与故障测试：`npm run test:embedding`。这些测试使用替身，不证明真实账户通过。真实接口检查也只证明小样本兼容，不代替完整索引、相关性和权限验收。此工具不是应用运行时适配器；落地时须复用其校验规则并完成服务端出站保护。

## 3. 工程入口

| 位置 | 职责 |
|---|---|
| `src/lib/ai/embedding.ts` | 模型、数量、index 顺序、1024 维、有限 float32 及非零向量校验 |
| `src/lib/ai/transport.ts` | 受信目标、全部 DNS 地址检查与连接绑定、TLS hostname、禁重定向、期限和响应容量 |
| `src/lib/ai/knowledge.ts` | Unicode 完整分片、有界来源发现及租约批次，不截取前缀 |
| `src/lib/ai/knowledge-evaluation.ts` | 可选诊断的真实查询向量、固定规则及来源命中统计 |
| `src/lib/ai/avatar-runtime.ts`、`knowledge-retrieval.ts` | 活动代际及模型绑定、相关性过滤、当前生命周期与阅读权限复核 |
| `src/app/api/admin/ai/index/route.ts` | 同源站主网关、构建／恢复／评测／切换，不自动重试未知付费请求 |

发布事务通过内部触发器登记来源版本与待扫描状态；后台分批登记具体项并执行外部调用。旧 `article_chunks.embedding` 保留用于历史兼容，不参与新分身的查询。公开问答只索引站主编辑的副本，私人原始会话排除。

## 4. 索引存储与任务执行

### 数据结构

追加迁移建立站主私有索引表，不修改已发布迁移。核心来源项与代际分开，另以 `knowledge_index_control` 管理来源版本和活动指针，`knowledge_evaluations` 保存可恢复评测：

- `knowledge_index_generations`：代际 ID、供应商受信 origin、精确模型标识、维度、预处理版本、分片版本、连接配置引用、状态及校验摘要。状态为 `building/ready/active/retired/failed`，一个活动代际，至多一个待切换代际。
- `knowledge_index_items`：代际、来源类型与 ID、来源版本／摘要、子片段序号、完整待嵌入文本、`vector(1024)`、`pending/leased/ready/failed/obsolete`、租约及尝试记录。同代际＋来源版本＋子片段唯一；`ready` 必须有有效向量。

两表启用 RLS，撤销 `PUBLIC/anon/authenticated` 的表与函数权限。只允许经过站主网关的服务端管理与检索；查询 RPC 限 `service_role`，固定 `search_path`、参数长度和返回条数。对来源、代际／状态、待运行任务建立索引；客户端不直接查询向量表或提交 SQL 条件。

来源只有当前可读的已发布／暂停文章片段与站主审核的公开问答稿。草稿、归档、私人会话、环境文件不进入索引。索引包含付费内容时，启用前由站主明确确认文字发送范围；数据库私有并不意味着第三方供应商收不到文本。

### 分片与增量

使用当前发布片段作为来源，不改变阅读正文或付费分界。规范化为固定版本的纯文本；每个索引子片段最多 **2048 UTF-8 字节**，在段落／句子边界优先拆分，超长段落按 Unicode 码点拆分，可带最多 256 字节前文重叠。保留来源定位与完整覆盖范围，不使用 `slice(0,2000)` 丢弃剩余内容。问题最多 1024 UTF-8 字节，空输入拒绝。

上述字节数是本应用的传输与分片约束，不伪称精确 token 数。供应商仍报告超长时，任务明确失败，不请求静默截断；中文、英文、长代码、emoji、组合字符必须进入真实长输入检查。BGE-M3 的问题和正文使用同一模型与处理规则，不额外套用其他 BGE 型号的查询前缀；模型卡说明本型号无需查询指令。

发布／修订／公开问答修改时，同事务登记来源变更及待扫描状态，旧版本项立即失效。后台按来源 ID 分页补齐全部项，覆盖超过 64 片的文章。外部响应回写时重新核对来源版本、摘要、代际和租约；期间有新修订、删除或取消公开则丢弃旧结果。权限变化先影响服务端验权与缓存，不等待重新生成向量。

### 可恢复执行

站主后台使用 `POST /api/admin/ai/index` 的 `step` 操作，每次执行一次有界来源扫描或一个最多 16 项的向量批次，总期限 20 秒；外部 Embeddings 请求最多 15 秒，响应最多 1 MiB。每项租约 90 秒，通过行锁认领；回写检查租约所有者，失效执行者不能覆盖新结果。关闭管理页停止继续派发，已确认进度保留；重新进入可继续，无需新增 Cron 服务或常驻进程。

后台明确显示总数、已完成、待处理、失败、过期来源及本次调用数。数据库查询／计数失败显示不可用，不显示完成。网络未知结果不自动重复付费调用；租约过期后须站主选择重试，并说明可能重复计费。数据库写入失败同样保留失败记录，不把未保存的向量计为完成。已保存的向量在同来源版本重试时复用，不再次请求。

发布成功不等于索引成功。后台关闭时新内容仍可发布，显示“待索引”；已有活动代际可继续检索仍与当前来源匹配的内容，不注入旧版正文。初始化、同步和重建均建立独立候选，站主确认后切换，不直接修改活动代际。同步候选在逐来源确认完整覆盖后，复制同连接、同处理规则及当前摘要一致的已确认向量；全量重建不复制。首次建库必须完整生成并由站主激活代际后才开放分身，不能因某一批成功便提前开放。

## 5. 模型切换与重建

1. 保存新连接为候选，先运行小样本检查。更改 origin、模型、维度、预处理或分片规则创建新代际，不覆盖当前向量。
2. 待切换代际构建期间，问答继续使用原活动代际的原连接、查询模型和当前来源项；不能用新模型检索旧向量。停用旧连接时分身暂不可用，不偷换新模型维持表面可用。
3. 仅在当前来源覆盖完整、没有失败／遗漏、真实检索评测通过后标记 `ready`。启用事务锁定代际及来源变更版本，发现构建期间又有发布则补齐后重新校验。
4. 原子切换活动指针，缓存包含代际 ID；旧代际暂留供兼容回退，后台明确列出与清理。首次没有可回退代际时保持关闭直至完成。
5. 同一受信 origin、模型与处理版本的 Key 轮换可只重验连接；若供应商更新权重或同名模型输出不一致，标记待重建。供应商没有公开 revision 时记为未知，不声称锁定了上游权重；保留合成探针摘要帮助识别变化，但不能保证发现所有漂移。

## 6. 检索、拒答与权限

每次提问先检查站主开关、知识库就绪、匿名规则、输入、频控与预算，再产生查询向量。缓存键包含代际、内容／权限版本、站主指令版本与读者有效权益；订阅到期须使缓存失效。缓存可在查询向量前按这些权威版本命中，不消耗生成次数。

检索只查活动代际，并重新连接当前来源版本与生命周期。MVP 首先采用该代际的**精确余弦搜索**，最多取 24 个候选，避免过滤后的近似 HNSW 把旧代际或无效来源挤占结果。通过规模基线后，若需 HNSW，再单独验证过滤召回与查询预算，不把近似结果等同完整召回。[pgvector 文档](https://github.com/pgvector/pgvector#filtering)说明了近似索引过滤可能少返回结果；1024 维无需修改现有向量扩展。

诊断允许 1–100 个已核对问题，无强制分组或配比。报告展示固定规则下的前五个不同来源命中率及库外返回数量，不表示回答正确率，不控制启用。新机制的初始阈值为 0.5；兼容的增量同步保留已启用代际的阈值。该数值是当前检索策略，不是普适的质量或安全标准；题目变化不调整它。旧策略报告按原规则读取，新旧结果不能直接比较。启用只由站主明确确认并通过完整覆盖、当前来源和连接校验。

候选经现有阅读权限代码再次判断。未购付费正文不进入生成上下文，只可提供标题、权限提示和合法链接。没有达到相关性门槛的可注入资料时，不发起生成；只有受限资料时返回阅读／购买入口，不以付费全文帮助生成答案。异常或超时返回暂不可用，不启用通用聊天或未经确认的关键词后备模式。

## 7. 出站保护与费用边界

首个适配目标固定为 `api.siliconflow.cn:443`，不允许访客、文章文字或后台自由路径决定调用目标。服务端统一出站层校验目标与 DNS 的全部 A/AAAA 地址，阻止回环、私网、链路本地及云 metadata，连接绑定已验证地址，禁止重定向。部署环境无法做到连接绑定时不开放任意自定义 origin，不能只做一次 DNS 检查便宣称防住重绑定。

Key 与受信连接引用绑定；同一供应商显式复用时仍分别测试生成和 Embeddings。向量服务接收的是文本，不能把“只用于检索”当作不向第三方发送付费正文的保证。日志仅记录代际、项 ID、错误代码、状态、耗时与脱敏用量，不记录原始供应商错误、文本或请求头。

站主需分别确认一次连接检查、一次全库索引的范围。后台预估待发送片段数和字节数；token 与实际价格未知时如实显示未知。访客检索频控独立于生成日限额，索引任务只允许站主启动，不因访客请求触发全库重建；不增加自动跨供应商重试。

## 8. 实施顺序与通过条件

| 批次 | 交付 | 必须通过 |
|---|---|---|
| 兼容性 | 当前检查工具＋离线回归；随后授权真实账户检查 | 真实 bge-m3 1024 维、批量顺序、中英文冒烟；同 Key 生成另验 |
| 配置与适配器 | 私有原子保存、凭据复用、统一出站、严格向量协议 | 非站主拒绝、目标绑定、重定向／内部地址拒绝、响应和期限边界 |
| 索引 | 两表迁移、增量登记、可恢复批次、代际切换 | 新装／升级等价，超过 64 片、中断与并发、旧响应、来源变化、写入失败 |
| 问答 | 就绪门槛、相关性评测、权限过滤、缓存及限流 | 空库／无命中不生成，订阅到期、未购不泄露、模型失配、关闭分身全端一致 |

数据库迁移必须通过生成无漂移、RLS 权限矩阵与真实 PostgreSQL 并发；供应商真实验证必须从实际部署网络再检查一次，不能以本机通过替代 Vercel。工程检查、真实供应商结果和部署验收分别记录，只有全部通过后才把“知识库可用”展示给访客。
