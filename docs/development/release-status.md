# 发布状态与验证范围

应用、SQL、部署说明与默认指南共同构成发布版本。数据库目标版本及生成工件以 [release-manifest.json](../../supabase/release-manifest.json)为准；部署者操作从[项目 README](../../README.md)和[部署指南](../deployment/guide.md)开始。

## 已有验证与复用

站主已使用候选源码包创建独立的新站，完成数据库、Vercel、域名、SMTP、站主认领和基础功能配置；过程中发现的密钥说明、变量分组、邮件模板与操作顺序问题已修正。后续功能在同一测试站按缺失增量升级，保留用户、内容、订单和权益。

| 范围 | 已有依据 | 更新后如何补验 |
|---|---|---|
| 新装与部署 | 源码包安装演练、实际域名与邮箱登录 | 初始化或配置流程改变时重走受影响步骤；其余步骤复用已有记录 |
| 数据库 | 新装／升级等价、权限检查、真实 PostgreSQL 并发；托管实例补丁先回滚演练再提交 | 追加迁移时重新核验结构、权限与原有数据；不重复运行安装文件 |
| 支付与邮件 | 实际小额支付、权益开通与通知收件；查单、重复结算及邮件幂等回归 | 收款与结算实现改变时验证差异；不为纯文档或界面调整重复付款、发信 |
| 内容、Skill 与插件 | 发布、权限与私有交付回归；实际后台与 Obsidian 使用反馈 | 按变更核对草稿、整辑发布、下载权限、同步及失败恢复 |
| AI | 连接、索引、权限、预算与协议回归 | 真实模型、匿名挑战和在线 Skill 仅在已授权范围调用；没有实际结果的功能不记为已验收 |

每份证据记录其代码提交、数据库版本与运行环境。一次性日志、截图和交易资料保存在权限受限的维护归档，公开文档只保留操作规则、验证方法与已知边界。

## 发布前核对

1. 最终提交通过 contracts、docs:check、lint、typecheck、build 和受影响回归；数据库变更另通过生成等价及真实 PostgreSQL 并发检查。
2. README 的安装顺序、升级表、环境模板和默认手册与当前实现一致；源码包排除真实配置、私有归档和机器状态，附 SHA-256。
3. 根据差异补齐实际部署检查；已有新站安装记录继续有效，不因每次功能迭代而要求整站重装。新增或变更功能按[验收矩阵](../contracts/acceptance-matrix.md)确认，未验证项如实保留。
4. 核对许可证、生产依赖安全与已知限制，确认正式分支、Vercel Source 和 Ready 状态一致，再公开仓库及版本。

## 运行与交付边界

- 后台内容 ZIP 用于复用内容与业务分析；整站恢复使用数据库、Auth、Storage 对象和部署配置，见[备份与恢复](../operations/backup-and-restore.md)。
- 付费正文、私有 Skill 包与会话按服务端权限和 RLS 交付。已下载文件不可远程收回，短时签名下载地址在到期前可能继续有效。
- Obsidian 仅上传草稿，权限、价格和公开发布在网页后台管理；本地删除不删除线上内容。
- 知识库问题测试用于诊断，不作为启用分数门槛；正文授权、完整覆盖、来源版本和连接一致性始终由代码检查。
- 自动化、截图或单项格式校验不替代真实业务结果。使用者未启用的可选服务，可保持关闭，不为基础安装验收强制开通。
