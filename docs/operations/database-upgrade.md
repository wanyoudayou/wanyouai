# 已有数据库升级

本指南用于已有万有AI 数据和用户的实例。全新项目使用[数据库安装步骤](../../supabase/README.md)，不需要执行这里的旧版升级脚本。目标数据库要求 PostgreSQL 17 或更高版本。

## 先确认已安装版本

在目标项目 SQL Editor 执行以下只读查询，确认是否有应用版本表：

```sql
select to_regclass('public.app_schema_version') is not null as version_table_exists;
```

返回 `true` 时，再查询已安装版本：

```sql
select version from public.app_schema_version where id = 1;
```

将结果与代码中的 [release-manifest.json](../../supabase/release-manifest.json) 的 `schema_version` 比较。已有应用表但没有版本表、没有版本行、版本超出下面的适用范围或曾手工修改结构时，先核对真实表、函数和权限；这些情况不能视为“空库”重新安装。

版本号相同只说明版本记录一致，不保证手工修改后的结构仍与源码一致。不要为了通过校验而直接修改版本行。

## 升级前准备

1. 按[备份与恢复指南](backup-and-restore.md)保存数据库、Auth、Storage 对象和迁移历史，在独立测试副本演练选定路径。
2. 从下表选择与已安装版本匹配的下一步，每个文件完整执行成功后再继续。已执行的迁移不要重复运行，不跨过缺失版本。
3. 涉及分身配额的升级，先关闭分身并等待旧请求结束；涉及商户订单编号的升级，先暂停收款并完成旧订单核对。具体条件见下文。
4. 数据库与应用代码配套更新。升级期间，不让旧应用继续处理受影响的付款、回调或生成请求。

### 分身配额升级

执行配额迁移前关闭分身入口，停止旧应用接收问答，等待已有问答结束；等待时间须覆盖旧版请求的最大执行时限。升级数据库并部署配套应用后，确认旧部署不再承接流量，再恢复分身。否则旧应用仍可能使用“先调用模型、后记用量”的旧逻辑。操作和验证见[分身配额说明](../development/avatar-quota.md)。

### 商户订单编号升级

组合脚本要求数据库版本为 `20261010053221`、站点收款开关 `payment_enabled=false`，且没有 `pending` 订单。先逐笔与支付平台核对旧订单的实际付款和归属，再按业务流程处理未完成订单；不能仅凭金额或碰巧相同的编号确认收款，也不能为了通过迁移而直接改订单状态。

该脚本在一个事务中完成编号变更和结算校验，锁等待上限 5 秒、单语句上限 30 秒。前置条件不符、锁等待或执行失败时会回滚；查明原因后再操作，不通过拆开脚本绕过检查。部署新应用后，结算只接受订单中保存的商户编号；旧应用使用本地数字 ID 或缺少编号的调用会被拒绝。回调及旧单处理规则见[支付契约](../contracts/payment-api.md)。

### 普通专辑与示例内容升级

从普通专辑迁移起，按上表依次执行到当前版本。这组迁移只增加结构与兼容函数，不自动插入指南、方案页或改变已有导航。先在副本执行缺失迁移和 `verify.sql`，再部署支持 `collection` 的应用。既有实例可由站主从部署检查主动载入示例；与已发布内容或仅有待审核修订的文档发生网址标识冲突时均会停止，已有内容不会被覆盖。

升级后如需回滚应用，只能退回支持 `collection` 及新发布事务的兼容版本；保留数据库和内容、订单、权益，不删除新类型或反向重放 SQL。迁移不会替代 Storage、Auth 或调度配置。

### 人机校验后台配置升级

人机校验迁移只增加公开 widget 配置列与站主专用的原子保存函数，不修改站主、内容、订单、权益或已有密钥。新列初始为 NULL，旧环境配置继续生效；站主首次在 `/admin/security` 保存或显式迁移后，以后台配置为准。数据库补丁先于配套应用部署，随后运行 `verify.sql`，检查匿名无法调用保存函数、普通用户不能读取私有密钥。迁移不会创建 Cloudflare widget 或自动开启挑战。

### 邮件与支付调度

邮件队列迁移不会给历史付款补发权益邮件。支付查单迁移增加待付单的检查时间列、索引和仅服务端可调用的领取函数，不改变既有订单状态。这两类迁移都不会自动启动任务；部署对应应用后，分别按[邮件调度](mail-scheduler.md)与[支付查单调度](payment-reconcile-scheduler.md)配置、核对并启用。

## 没有版本表的早期实例

[complete-v1-to-release-baseline.sql](../../supabase/upgrades/complete-v1-to-release-baseline.sql)只适用于结构已经与 [legacy-install-order.json](../../supabase/legacy-install-order.json) 中应用 SQL 一致的早期实例，不是任意旧库的通用升级器。该清单中的 `seed.sql` 是演示数据，不在已有实例执行。

先在测试副本核对表、函数、权限及扩展。若缺少 `legacy/v1-owner-bootstrap.sql` 或 `legacy/v1-booking-authority.sql` 的结构变更，需先审查并补齐；存在其他差异时，先解释并处理差异，不能猜测重放整个目录。

确认匹配后，执行该一次性升级文件，它会调整向量扩展位置、函数和角色权限，并写入版本 `20260928124423`，不导入演示数据。然后从上表对应版本继续执行缺失增量。较新实例不得重跑这个旧版升级文件。

## 升级后检查

完成所选版本的全部迁移后，运行与目标结构匹配的 `verify.sql`，确认每个检查项的 `passed=true`，并部署配套应用。使用真实身份检查注册登录、正文权限、内容发布，以及启用的支付、邮件、核销和服务功能；全部正常后再恢复受影响入口。

从旧版本升级不会自动公开原始分身会话；公开问答保存为站主另行编辑的稿件。也不要通过重写交易、权益或历史用量，使数据看起来符合新版本。结构或权限不符合预期时停止切换，回到备份副本排查。

若要从 SQL Editor 管理方式改用 Supabase CLI，另按[迁移历史衔接](migration-history.md)核对和同步迁移记录；应用版本表不能代替 CLI 历史。

### 统一 AI 与知识库升级

从 `20261020090813` 升级时，先备份并关闭旧分身，依次执行上表两份 AI 增量，再运行当前 `verify.sql`，最后部署配套应用。新增表和函数不自动调用供应商、不自动发送文章、不覆盖既有连接配置。首次从 `/admin/ai` 显式迁入或填写连接，完成连接检查、完整索引并由站主确认后启用分身；旧 `article_chunks.embedding` 不认证为新索引。

新应用只使用后台连接。旧环境变量可在迁入和实际检查通过后删除，不能依靠应用回滚恢复旧的全文后备或未版本化向量路径。数据库、内容、订单及权益保留，旧索引的清理只通过后台受控操作；不要反向执行迁移或删除应用表。

### 知识库启用与诊断升级

`20261023112358` 将问题测试与启用分离。先备份，在副本运行增量与校验，再应用到实例并部署配套代码。已有内容、向量、报告和活动索引保留，不自动启用候选、不调用模型。新候选完整生成后由站主明确确认；可选测试允许 1–100 题、无最低命中率。历史报告按原规则保留，编辑题目不训练向量。旧应用的报告确认接口会要求刷新；不要回退到依赖分数启用的旧界面。

### 独立 Skill 与手册同步升级

1. 备份数据库与 Storage。在测试副本按上表执行缺失结构增量，运行目标 `verify.sql`。结构迁移本身不转换原内容、不改订单或权益。
2. 部署支持 `articles.type=skill` 和手册兼容地址的应用，核对部署 Source。按 [Skill 指南](../deployment/skills.md)配置私有桶。新功能验收完成前不添加收费包或启用在线生成。
3. 转换旧内容前暂停后台发布和插件同步。在 SQL Editor 执行：

   ```sql
   begin;
   select public.migrate_content_kinds(id)
   from public.profiles where is_owner;
   rollback;
   ```

   返回转换数量且没有报错后，将最后一行改为 `commit;`，完整执行一次正式转换。该函数把旧普通专辑保留 ID 改为手册，并为旧技能建立固定映射；已转换对象重复执行不新增。若出现 `SKILL_SLUG_CONFLICT`，先在后台处理与旧技能同标识的文章／待审核稿，再重试，不删交易或改主键。
4. 再运行 `verify.sql`，核对原手册、技能章节、已购内容和待付订单。新 Skill 没有包时不展示购买入口。站主可开始在独立 SKILL 后台添加包，在 Obsidian 连接页创建专用凭据。

应用回滚只能退回兼容独立 Skill 和新同步协议的版本。保留数据库、不可变包、会话、订单、权益及文章版本，不反向重放 SQL。需要恢复转换前状态时使用完整备份在隔离副本演练，不能删除新表冒充回滚。
