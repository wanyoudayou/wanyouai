# 万有AI · 页面契约

`/admin/media` 为站主素材库：分页图片网格、名称搜索、排序、上传进度、详情、替代文字、引用检查与归档恢复。非站主进入既有后台登录／无权限流程；读取错误与空目录区分。正文、封面、横幅、头像、Logo 和自定义 HTML 复用同一模态选图窗口，关闭返回触发点焦点，不提交外层表单。图片权限和上传协议见[素材库契约](../contracts/media-library.md)。

> 本文档定义 MVP 全部路由的**块级结构契约**：每个页面自上而下有哪些区块、数据来自哪张表、匿名/注册/已购三态如何分叉、无数据时长什么样。它不是视觉稿——间距、字号、色板见《[设计规范](design-tokens.md)》。

## 0 · 一条总原则，先于一切布局

四张参考页（YouMind Boards 空态与有内容态、FlowUs 文档页、Perplexity Connectors）全是登录后的工作区内部，没有一张营销首页。这个信号按字面读就是答案：

**万有AI 整站就是一个工作区。** 初期给人的直觉是飞书笔记 / GitBook 式的**记录平台**，未来在此骨架上扩展成**工作平台**。（「日志 / 行事历 / 仓库」是理解用的类比——站内命名一律用 PRD 一套：博客、专辑、手册、技能、活动、服务、名片；类比不进界面。）布局的使命不变，按序：

1. **可信**：陌生访客 10 秒内看懂「这是谁、卖什么、凭什么信」；
2. **易得**：找到内容 → 读完免费部分 → **就近**遇到购买入口（导购不推销）；
3. **可运营**：站主一个人能在同一骨架内完成全部供给与订单动作。

达成方式：**全站统一左中右三栏**——左栏导航、中栏阅读、右栏交互。店面即工作台，分身坐在右栏柜台。

## 2 · 全局骨架：统一三栏

```
┌─────────┬──────────────────────┬─────────┐
│ 左栏·导航   │      中栏·阅读           │ 右栏·交互   │
│ 站名      │   当前页面主体（§3 各路由）     │ 对话区      │
│ 内容地图    │                      │ （与分身：   │
│ （专辑内嵌  │                      │  聊天室/    │
│  章节树）   │                      │  私聊）     │
│ ───────  │                      │ ⇄ 本页目录  │
│ 身份区+订阅  │                      │           │
└─────────┴──────────────────────┴─────────┘
```

**三栏各自纪律：**

- **左栏回答「这里有什么」**：站点 Logo（`identity.logo_url`，缺省为站名首字标）+ 站名 + 内容地图 + （专辑内）章节树；底部身份区 + 订阅 pill。不含任何交易动作。
- **中栏回答「正在读什么」**：当前路由的主体内容（§3 逐路由定义）。阅读列固定可读宽度；列表与表格页可放宽。
- **右栏回答「可以聊什么」**：与分身的对话（本页聊天室 / 私聊），可与本页目录切换。**购买动作不入右栏**（导购不推销：交易入口长在内容锁定处，见 2.5）。

### 2.1 左栏 · 导航

- **内容地图**（命名与 PRD 统一，全站只此一套词汇）：博客 `/blog` · 手册 `/handbooks` · 技能 `/skills` · 活动 `/events` · 服务 `/services` · 名片 `/card`（名片页与 `/card.json` 同源）。其后追加站主自定义页（`nav_label + nav_order` 配置，FileText 图标）。
- **「专辑」是后端概念**：series 表统一承载手册/技能/活动（万物皆专辑，PRD §4.2），但它是内容组织形式，**不是栏目**——不出现在导航、页面标题与公开 URL 中。公开路由一律按类型命名（`/collections`、`/handbooks`、`/events` 及各自 `[slug]`），四个详情页共用同一组件（见 3.5）。工作台类比（日志 / 行事历 / 仓库）同样不进任何界面与文案。

- **专辑内行为**（GitBook 式）：进入类型详情页（`/handbooks/[slug]` 等）后，左栏下方展开该专辑**章节树**（含权益状态图标），顶部保留「← 返回栏目」回到对应栏目。未购时章节树可见、锁定章节点开 → 中栏节选 + paywall。
- **底部身份区**（三态，见 2.4）+ 订阅 pill。
- 外观切换为单个 pill 按钮，显示当前偏好的图标与文字，点击按“跟随系统 → 浅色模式 → 深色模式 → 跟随系统”循环。前后台与移动目录交互一致，切换保留当前表单和编辑内容。

### 2.2 中栏 · 阅读

- 各路由主体即中栏内容，块级契约见 §3。
- Footer 收在中栏底部：© 站名 · 退款政策（页面选择器）· 发布位置=底部的自定义页链接 · 联系方式（信任出口由左栏「名片」承担，不再重复）。

### 2.3 右栏 · 交互

主视图是**对话区**（与分身），可与**本页目录**切换（仅当页面有目录时出现切换项）。**出现范围**：首页和内容详情按页面需要常驻；其他公开页面可从移动入口按需打开。折叠形态：≥1280 用表头折叠符号**完全收起**（不保留窄条，主栅格退回两列），页面右上角悬浮机器人图标点开还原；768–1279 使用图标栏，分身按需展开；<768 由底部“分身”入口唤起抽屉：

1. **对话区——同一分身，按页面锚定分两种形态**（PRD §4.2 / §4.6 既定）：**聊天室不是独立容器**——索引只有一份，页面入口 = 钉载 + 加权：门票改变席位与对话归宿（挂该文、可公开），不改变可探索范围（全域检索，验权只看用户权益）；
   - **本页聊天室（专题讨论）**：文章页与专辑 README 页。访客在室内**与分身**就本页内容对话（按 §3 配额；缓存与检索命中优先应答），参与者实时可见；对话默认**待审核**，站主另行编辑公开问答稿并确认移除个人信息与受限正文后公开——原始对话保持私有，公开稿人人可读并进入分身检索层（相似问题被历史讨论直接命中）；展示公开讨论数（置信度的事实信号，不做评分）。讨论区是与分身的对话，**不是人际论坛**。
   - **1:1 私聊**：其余页面（首页、列表页等）。与分身自由问答，不进房间、不公开；首页可由名片 Hero 的问句输入框直接唤起（见 3.1 纪律）。
   - **输入框**：多行文本域（按内容自增高），右下角为发送按钮；Enter 发送、Shift+Enter 换行（输入法组合中的 Enter 不发送）。
   - **@引用（补发门票）**：输入框 @ 已发布内容（模糊匹配 + 自动补全）= 为会话追加钉载与加权，聊天室 / 私聊通用；未购命中仅注入预览与占位（验权只看用户权益）。
   - 标注常驻在面板头部副标题「AI 生成 · 仅供参考 · 合作请转人工」；「转人工」点击后输入区切换为留言区，「取消」或提交后回到 AI 对话。当前不提供全屏 /chat 路由。
2. **本页目录**：长文 / README 的页内 outline（锚点跳转），与对话区切换。
3. **会话未开始的占位内容按页面上下文渲染**：首页 = 轻量名片卡片区（`CardPanel` compact 变体：头像居中 + 身份/专注领域/供给/约束/不接，与 /card 完整名片同源）；内容 / 讨论页 = 默认 tips 列表；其余页面 = 默认招呼语。占位是会话区的「台面摆设」，不改变「会话只有一个家 = 右栏」。
4. **购买动作不入右栏**（导购不推销：交易入口长在内容锁定处，见 2.5）。中栏文末只留轻入口「本页讨论（N）→」唤起右栏，不在正文堆长评论区。

### 2.4 三态与订阅 pill

三态差异全部落在**左栏底部身份区**，导航永不变——身份变化不该改变站点地图：

| 状态 | 左栏底部 |
|------|---------|
| 匿名 | `登录`（次级）+ `订阅`（强调色 pill） |
| 注册未订阅 | 圆形首字头像 + 「会员中心」（邮箱首字符，点击进 /me：我的权益 · 订单 · 登出）+ `订阅`（强调色 pill） |
| 已订阅 / 持权益 | 头像（含订阅徽章）——**订阅 pill 消失** |
| 站主 | 头像 + `网站管理` 区段（单入口，见 3.13） |

订阅 pill：全站唯一常驻销售元素；无横幅、无弹窗；paywall 场景下让位于就近 CTA（见 2.5）。

### 2.5 Paywall 引导 = 上下文函数

原则：**就近优先**——CTA 跟着用户正在触碰的内容单元走，不升维推销。

| 触达场景 | 主 CTA | 次 CTA | 理由 |
|----------|--------|--------|------|
| 文章页（锁定章节） | 单篇购买 | 所属专辑 | 用户正摸着这篇文章 |
| 专辑页 | 专辑购买 | 订阅 | 决策单元是整个专辑 |
| 列表页节选占位 | 订阅 | — | 粒度太散，只指路不推销单件 |
| 已订阅遇 paid-single | 继续阅读 | — | 全站订阅已覆盖，隐藏购买引导 |
| 活动沉淀（纪要 / 资料） | 订阅 | 购票（仅报名期收费活动） | 参会资格即解锁（PRD §4.5）；已参会者无 paywall |

paywall 块统一用 FlowUs 式 callout：节选末尾 + 权益说明 + 价格 + 主/次按钮。占位不放价格之外的营销话术。

**订阅交叉卡（双轨并列，PRD §4.3）**：单买主 CTA 旁固定放订阅引导卡——「订阅解锁全站付费内容与专属内容，本专辑 / 本篇也包含在内」+ 订阅价 + 入口；已订阅者不显示，单篇也按已解锁展示（上表末行）。

### 2.6 响应式与中间态底线

- **桌面 ≥1280**：三栏全展开。
- **768–1279**：左侧图标栏，完整目录和右侧分身按需打开。
- **<768**：底部首页、目录、分身、我的；目录与分身抽屉互斥，未启用分身隐藏入口。单栏与安全区避免遮挡操作。
- **加载态**：列表页骨架卡占位；阅读页正文区骨架。
- **错误态**：404 用统一空态组件（插画 + 返回首页）；权限不足不单独弹窗，一律并入 paywall 块呈现。

### 2.7 未来扩展：工作平台化

三栏是常量，内容是变量。未来加协作、任务、客户工作台等工具，都在右栏/中栏长出新分区，**不换骨架**——这是把参考选成清一色工作区的原因：它们各自长出了不同工具，但骨架同构。

## 3 · 路由契约总表

| 层 | 路由 | 目的 | 中栏形态 | 左栏 / 右栏差异 |
|----|------|------|-----------|----------------|

| 获客 | `/blog`、`/blog/[slug]` | 博客列表 / 阅读 | 工具条 + 卡片网格 / 单列阅读 | 文章页右栏=本页聊天室 |
| 获客 | `/handbooks`、`/events`（含各自 `[slug]`） | 三个类型栏目 / 专辑详情 | 卡片网格 / README+章节阅读列 | 详情页左栏=章节树 |
| 交易 | `/services`、`/services/[id]` | 服务列表 / 详情 + 询价 | 卡片网格 / 六要素 + 表单 | 标准 |
| 交易 | `/me`、`/me/orders/[id]`、`/login` | 权益 / 订单追踪 / 登录 | tabs / 时间线 / 单屏 | 标准（/login 可暂隐左右栏） |
| 交易 | `/checkin/[token]` | 活动现场核销 | 单屏：报名者身份（owner 视角）+ 核销按钮 | 无布局（暂隐左右栏，同 /login） |
| 信任 | `/card` | 人类可读名片（与 /card.json 同源） | 结构化名片页 | 标准 |
| 机器 | `/llms.txt`、`/card.json` | Agent 接口 | 纯文本 / JSON | 无布局 |
| 后台 | `/admin/*` | 站主运营 | 同骨架，宽表格可折叠双栏 | 左栏=后台区段 |

以下逐路由展开。三态统一记为：**匿**（匿名）/ **注**（注册未购）/ **购**（已持对应权益）。

### 3.1 `/` 首页（固定模板：名片 Hero + 五个内容分区，配置管显隐与文案）

| #   | 块（中栏自上而下）                                           | 数据源                    | 说明                       |
| --- | --------------------------------------------------- | ---------------------- | ------------------------ |
| 1   | **名片 Hero**（第一人称 + 大 banner 背景图，图源 `home_config.hero.banner_light_url` / `banner_dark_url`，分别对应浅色和深色模式，单侧留空时使用该模式的内置背景；文字与控件自动跟随主题，正文无嵌套底板；自定义图片保持原色，通过全幅渐变保护文字）：第一人称一句话（帮谁·做什么·交付什么；`whitespace-pre-line`，在配置文案内换行即手动断行）+ **事实徽章行** + **问句输入框**（纪律见下）+ 专注领域与「不做什么」一行摘要。订阅 pill 仅左栏底部常驻（§2.1/2.4），Hero 内不渲染 | site_config + 同 /card 数据源 | happyaicoding / fde4 名片式 Hero + mdldm 问句框；合并 v0.3 的「站点说明卡」与「OPC CARD 卡」 |
| 2   | 博客：最新文章卡片带（含计数 +「查看全部」）                                     | articles(type=blog) 按发布时间倒序        |                          |
| 3   | 手册：手册专辑卡片带（含计数 +「查看全部」）                                     | series(type=handbook)，featured 置顶优先、其余按更新；封面取 README 文章 `cover_url`，无封面回退类型占位图标 | 精选 = 站主置顶，无算法 |
| 4   | 技能：技能专辑卡片带（同手册）                                          | series(type=skill)，同上                  |                          |
| 5   | 活动：upcoming/registering 状态的活动卡                                | event_details                 |                          |
| 6   | 服务：服务卡 + 「查看全部」                                          | services                      |                          |
| 3   | 最新博客：最新 6 篇文章卡片                                     | articles(type=blog)    |                          |
| 4   | 即将活动：upcoming/registering 状态的活动卡                    | event_details          |                          |
| 5   | 服务入口：服务卡 + 「查看全部服务」                                 | services               |                          |

- **三态**：中栏块内容一致；身份差异在左栏底部（见 2.4）。
- **空态**：每块独立空态（无活动则整块隐藏）。
- **配置边界**：名片 Hero 固定首屏（`hero.enabled` 显隐）+ 首页自定义区（`home_config.custom_zone`，Hero 与五块之间，与自定义页面共用净化管线）+ 五个内容分区（博客/手册/技能/活动/服务）固定模板；site_config 只管每块**显隐 + 顺序 + 文案**，不提供自定义块插槽——首页结构是产品判断，不是配置项。
- **取数边界**：分区动态调用——手册/技能 = 置顶 featured 优先、未标回退该类型最新 published（部署零配置即有内容）；博客 / 活动 / 服务 = 时间与状态自动，随发布 revalidate；**无个性化（所有人同一首页）、无算法推荐（精选是站主编辑动作）**。

**事实徽章纪律**（card.schema「声誉不自陈」的界面化）：徽章只放**可验证事实**——专辑数、文章数、更新节奏、订阅价格、服务容量（如「本月 3/4 单」）；不放自评分、不放自标签式信誉；声誉一律指向 evidence（落地评价页 URL），首页不复制评价内容。

**问句输入框纪律**：输入框是右栏对话区的**首屏快捷入口，不是第二套聊天**——提交后唤起右栏（<768 为底部抽屉），问题自动带入，会话历史与配额仍在右栏（会话只有一个家）。placeholder 只锚定站内供给的问题（site_config 可配，如「这份手册适合我吗？」；可 @ 直接指名站内供给，见 2.3），不暗示通用 AI 助手（分身只答检索层能支撑的范围，PRD §4.6 注入防线）。匿名生成按开关、Turnstile、日配额与站级月限额开放；未配置时引导登录。

**参考采纳对照**：

### 3.2 `/blog` 博客列表

- 块：工具条（搜索 + 排序：新→旧/旧→新）→ 文章卡片网格（封面/标题/日期/摘要截断/权限徽章 free·subscriber·paid-single）。
- 数据源：articles(type=blog)。
- 三态：卡片徽章随权益变化（paid-single 已购则显示「已购」）；其余一致。
- 空态：插画 +「还没有公开文章」+（站主视角）「去后台发布」。

### 3.3 `/blog/[slug]` 文章页

- 块：标题区（标题/日期/标签/封面）→ 正文阅读列 → **paywall 块**（截断 offset 处，上下文函数见 2.5）→ 文末：版权行 + 所属专辑链接 + **落地评价入口**（注册且可读该文者可评：评分+文字，与公开讨论共同构成置信度，PRD §4.2）+ **「本页讨论（N）→」轻入口**（聊天室在右栏）。
- 数据源：articles + bodies（bodies_read 权限分支）。
- 三态：**匿/注**=节选 + paywall（右栏聊天室按 §3 配额仍可用——匿名也是分身的第一演示）；**购**=全文 + 落地评价资格。
- 空态：404。

### 3.4 `/handbooks`、`/events` 三个类型栏目

- 同一套组件、三个预设（type=handbook / skill / event）；「专辑」是后端概念，不入 URL 与标题（见 2.1）。
- 块：工具条（搜索 + **权限计数 chips**：「全部 · N」「免费 · N」「订阅 · N」「单篇 · N」+ 排序）→ 专辑卡片网格（封面或 emoji 占位/标题/章节数/权限徽章；活动加日期徽章；技能卡以**产出物预览**为主视觉——skillry 式）。
- 数据源：series（type 过滤）+ event_details。
- 栏目筛选按已发布普通章节的 access 聚合（README 不计入章节数与权限统计；无普通章节时按公开介绍归类）：免费=public，注册=registered，订阅=subscriber 或 paid；同一专辑可命中多个筛选，计数为专辑数。单篇仅适用于独立 paid 博客，栏目中为 0 时隐藏。权限筛选不代表购买授权。
- 手册 / 技能按 updated_at 排序；活动按 starts_at，默认最早优先。活动票价仅取 ticket_price，null 显示「票价待定」，0 显示「免费参加」。
- 取数失败显示加载失败与重试；成功返回 0 条才显示空态。
- 三态：一致（徽章随权益，已购显示「已购」）。
- 空态（各自文案）：手册「手册编写中」/ 技能「技能整理中」/ 活动「暂无排期」，统一插画 + 单动作「去博客看看」。

### 3.5 `/handbooks/[slug]`、`/events/[slug]` 专辑详情（全站最重的页面，共用专辑组件）

- **左栏**：切换为该专辑**章节树**（章节列表 + 当前高亮 + 各章权益状态图标），顶部「← 返回栏目」回到对应栏目（/handbooks 等）。
- **中栏**：
  - README landing（未购首屏）：封面 / 标题 / **任务一句话（series.task，缺省回退摘要）** / 标签 / **人群 chips（audiences，静态无跳转）** / 章节目录预览 / 类型化块；
  - 章节正文（已授权）：阅读列 + 文末「本页讨论（N）→」轻入口（聊天室在右栏，仅 README 挂聊天室，章节页为私聊）；
  - 顶部常驻条（类型化）：
    - event → 报名块 callout（状态：upcoming/registering/ended；门槛在报名不在阅读）；
    - handbook → 无额外块。
- **右栏**：标准交互——README 页=本页聊天室，章节页=私聊，本页目录可切换（如有）。
- 数据源：series + readme_article_id 指针 + articles(type=chapter) + event_details。
- 章节锚定：专辑详情保持 `/handbooks/[slug]`、`/skills/[slug]`、`/events/[slug]` 单层路由；当前章节用 `?article={article.slug}` 锚定，不新增嵌套路由。
- 三态：**匿/注**=README + 章节标题与预览可读，锁定章节点击 → 节选 + paywall（手册 / 技能：主 CTA=专辑；活动：参会资格引导——订阅 / 报名期购票，见 2.5）；**购**=已授权章节与符合资格的报名动作；旧技能章节链接兼容保留，包交付使用独立 Skill 页面。
- 空态：404；无章节专辑 → README + 「编写中」占位。
- 机器可读：页 SSR HTML 内嵌 JSON-LD——skill 专辑 `SoftwareApplication`、手册 / 活动 `Product`，`offers` 与页内价格同源（PRD §4.7）。

正文与 JSON-LD 实现说明：JSON-LD 采用当前 Next.js App Router 推荐的 page / layout 原生 script 输出，位于 SSR HTML 中；不在页面内嵌套 head。Markdown 正文与预览共用服务端渲染器，原始 HTML 不执行；Mermaid 使用服务端静态 SVG 白名单消毒，无法渲染的语法显示源代码。图片通过安全 HTTPS / 本站地址显示；SVG 文件需在发布管线完成消毒或转码后再接入，当前正文图片组件保守拦截原始 SVG。

### 3.6 `/services` 服务列表

服务卡片展示已发布服务的名称、交付物、价格和容量；不同身份目录一致，无内容显示“暂不接单”，查询失败显示错误和重试。

### 3.7 `/services/[id]` 服务详情

六要素 → 站主约束 → 询价表单 → 流程说明与评价。字段为 intent/budget_range/deadline/context_links，匿名还需联系邮箱；端点 `/api/services/inquire`。不同身份均可询价，已登录客户可追踪服务订单。容量满显示排期提示，不伪造可立即接单。不存在/不可见服务为 404。

### 3.8 `/me` 我的权益

- 块（中栏页内 tabs：**权益** / **订单** / **活动报名**）：
  - 权益：订阅状态卡 + 专辑/单篇/活动权益列表（entitlements）；
  - 订单：订单卡列表 → 点击进 `/me/orders/[id]`；
  - 活动报名：报名记录 + 状态 + **核销二维码**（upcoming/registering 场次出示，核销页见 3.15）。
- 数据源：entitlements + orders + event registrations。
- 空态：每 tab 独立空态 + 单动作（「去逛专辑」「去看服务」）。

### 3.9 `/me/orders/[id]` 订单追踪

- 内容订单块：订单头（商品名 / 本站订单编号 / 状态 / 金额）→ 时间线（创建订单 → 本站确认收款 → 权益开通）；待支付状态按站点收款配置显示渠道入口。
- 数据源：本人 orders + 同一订单的 entitlements（`source=order`、`source_ref=order:{id}`）；只允许本人读取，依赖 RLS 并再次比对 user_id。
- 时间线采用站点 `identity.timezone`，明确显示时区；不依赖服务器默认时区。创建时间取 `orders.created_at`，本站确认收款时间取同事务产生的订单权益 `created_at`，权益开通时间取 `starts_at`。缺失记录显示未知或待完成，不将订单后续更新的 `updated_at` 当作付款时间。
- 「本站确认收款」表示本地支付核验与权益事务完成，不冒充支付平台扣款时间；页面说明两者可能有时间差。
- 服务履约在 `/me/services/[id]` 展示 bookings + milestones 的询价、报价、条款确认与里程碑时间线；不与内容订单编号混用。

### 3.10 `/login`

- 单屏邮箱输入、验证码与邮件链接；无密码登录，经 Supabase Auth SMTP 发信。
- 用户登录回调 `/login/callback` 不认领站主；站主使用 `/admin` 与 `/auth/callback`，由已验证 OWNER_EMAIL 限定首次认领。
- 登录失败显示明确反馈，不能把网络异常当作未登录成功。

### 3.11 `/card` 名片页（信任层）

- 块：站主头像（`identity.avatar_url`，缺省站主名首字标）+ 身份（display_name / one_liner / 时区 / 语言 / focus_areas）→ 供给（services / content_offerings / skills）→ 约束（工作时段 / 响应 / 容量 / 不接事项）→ 协议（询价字段 / 人类通道 / escalation）→ **实证**（自媒体平台露出 `identity.social_links`——预设 X/GitHub/小红书/小宇宙/公众号 + 自定义，逐条添加；evaluations 指针随交易上线开放——只放指针，不自陈）；各分区标签带 lucide 图标。
- 数据源：**与 `/card.json` 完全同一数据源渲染**（card.schema.json `source_of_truth` 纪律；人类页是 JSON 的友好视图，不是另一份内容）。名片与约束字段经后台「名片」维护（见 3.13），一处改动两处同步。
- 三态：一致（这是给人和 Agent 看的公开事实页）。
- 渲染：浅灰铺满 main 区域 + 三栏——左身份栏（CardIdentityAside：大头像/图标事实行/CTA/bio/tags）· 中列内容卡片（CardPanel：供给/约束/不接/协议/实证）· 右列自定义区（`identity.custom_zone`，AI 生成约束卡片型 cp 类：cp-link-cover / cp-social 等）；与首页右栏 compact 占位共用组件（一处组件、两处表面）；数据源与 `/card.json` 同一数据函数。

### 3.12 机器路由

- `/llms.txt`（访问级别与专辑任务）、`/card.json`（schema 校验）保持无布局。名片身份栏提供默认折叠的“供 AI 读取”入口，可查看与复制公开地址；复制失败显示手动复制提示，不显示成功，页面不展示协议版本号。
- 页内 JSON-LD：专辑详情页与单卖文章页 SSR HTML 内嵌 Product / SoftwareApplication + Offer（与页内价格同源，见 3.5 与 PRD §4.7）——机器可读的第三层，非独立路由。

订单列表、`/me/orders/[id]`、`/checkout/[orderId]` 及后台收款订单详情提供对应内容入口：单篇到文章，专辑到其类型路由，活动到活动详情，订阅到我的权益。入口仅读取标题、标识和生命周期；草稿、归档、类型不匹配或不可读取时不生成内容链接，目标页仍独立鉴权。

### 3.13 `/admin/*` 后台

唯一站主会话守卫覆盖页面与写入动作，普通用户不能进入。后台采用分组左栏：概览；内容（文章、专辑、独立页面）；业务（收款订单、服务与履约、用户与权益、收件箱）；设置（首页与导航、站主名片、站主分身）；维护。手机使用菜单抽屉。

内容工作台/导入/审核共用发布函数；元数据列表不批量读取受限正文。用户明细提供订单和权益，不承诺在此显示分身对话。

名片与站点配置独立保存。首页与导航管理首页、订阅/收款；站主分身使用独立设置页；密钥不回显，留空保持现值。分身说明只提供配置决策所需信息，内部存储与权限见开发契约。

`/admin/security` 为站主专用“安全与人机校验”，管理 Turnstile 开关及密钥对。配置与私有密钥同事务、保存冲突拒绝覆盖。新请求即时读取；匿名分身与匿名询价共享 widget、使用不同操作类型。此页不配置 Supabase Auth CAPTCHA，详见部署指南。

匿名分身的首页快捷提问与右栏输入共用发送闸门：输入有效问题后，点击发送或按 Enter 才打开居中校验弹窗，平时不加载挑战控件、不占输入区。通过后关闭弹窗并只发送一次原问题；取消、Esc 或点遮罩关闭时保留问题及引用，恢复入口焦点。验证加载失败或过期提供明确提示和手动重试，不调用 AI；已登录用户直接发送。手机对话抽屉中的校验弹窗保持独立焦点，不关闭原对话。

服务订单页展示状态、客户条款确认和检查点动作；只提供当前状态允许的操作，整单验收仅客户侧；已结束只读归档。活动提供详情、报名名单、名单/扫码核销与 CSV。

### 3.13.4 `/admin/setup` 部署检查与首次配置

- 仅站主可访问；页面与数据函数均先验证会话及数据库站主身份，再读取部署环境和创建服务端诊断客户端。匿名或非 owner 跳转 `/admin`。
- 复用后台分组导航，窄屏检查列表纵向展示。按基础条件、首次内容、邮件、支付、自动任务、AI 与匿名人机验证、人工基础验收分组。登录 SMTP 与应用事务邮件分别呈现，后者部分缺失时只显示缺少的变量名，不显示值。
- 与 CLI 共用配置及 Storage 检查规则；读取实际 app_schema_version 与代码发布清单比较，读取真实 site_config、图片桶限制和已发布文章数量。分身只检查密钥记录存在，不读取密钥值；内容只计数，不读取正文。检查不写入数据；示例载入为独立、显式确认的操作。
- 运行条件增加权益邮件队列健康：只读 service RPC 的聚合状态；有终止任务或超过 10 分钟的到期积压显示待配置，连接失败显示检查未通过。提示每分钟外部调度；空队列不能证明发信或调度运行，未启用发信时仍显示已有队列的异常。不输出收件人 / 正文 / 任务身份，也不在刷新中执行 worker。
- 状态明确为符合条件 / 待配置 / 未启用 / 检查未通过 / 待人工验收；远程故障保留其他检查结果，禁止用默认配置判定通过。自动条件通过不代表交易、SMTP、RLS、Storage 对象权限或备份恢复已验收。
- 首次配置链接「名片」与「内容工作台」，提供外部环境修复步骤。人工验收提供可键盘展开的“如何验收”步骤与预期结果，邮件／支付／分身分组各自提供验收；业务关闭时对应人工项显示未启用并隐藏步骤。基础人工项始终待人工验收，状态不持久记录；刷新重新读取，不输出配置值或原始错误，不发送邮件或测试支付。
- 名片首次保存必须提示站名、站主、一句话和联系邮箱 / 预约页面二选一；服务语言字段展示 `zh-CN`、`en` 等代码示例，校验失败指出具体字段。用户必须看到保存成功提示后才把部署检查的名片项视为完成。

### 3.13.5 `/p/[slug]` 自定义页

- 块：整页即净化后的自定义 HTML（cp-* 语义类承载全部样式）；AppShell 响应式导航保持一致。
- 发布位置 `placement`：左侧栏（左栏导航链接）/ 底部（页脚链接区）/ 不固定（默认，仅直达链接）；显示名称 = `nav_label`，缺省用页面标题，排序 = `nav_order`。
- 三态：一律公开（无付费墙 / access 分级）；`draft` / `archived` 即 404（`published` 可见）。
- SEO：标题、描述、canonical 和分享信息来自公开元数据；有公开封面时附分享图，无封面时使用文字摘要，不预置品牌照片；不进 llms.txt / card.json。
- `/p/pricing` 是可编辑普通独立页。`cp-pricing` 输出当前年度价格、功能区别和真实配置状态，配置不完整时禁用购买，不承诺自动续费。
- 净化：读取 + 渲染双道 sanitize-html 白名单（结构/排版/表格/图片标签 + cp-* class + https/mailto/站内链接；禁 script/style/iframe/form/事件属性）。

### 3.14 全屏会话边界

当前分身在右栏，不提供 `/chat` 全屏路由。

### 3.15 `/checkin/[token]` 核销页

- 单屏（暂隐左右栏，同 /login）：非 owner 打开 = 活动名 +「请出示给站主」（零 PII）；owner 打开 = 报名者姓名/邮箱 + [核销成功] 按钮——服务端判 owner，点击原子完成 attended + 发票（PRD §4.5），幂等（重复打开显示已核销）。
- token = registrations.checkin_token（uuid，不可猜）；站主手机首次扫码经 magic link 登录（会话常驻）；兜底 = 后台名单手动标记（同一服务端动作）。

## 4 · 后台交互与权限补充

### 内容生命周期与列表

文章 `/admin/articles`、专辑 `/admin/collections`、独立页 `/admin/pages`、服务 `/admin/services`、收款 `/admin/payments`、用户 `/admin/users`、收件 `/admin/inbox` 与会话 `/admin/conversations` 共用服务端列表契约。参数为 `q/status/type/sort/page/pageSize`，章节附 `series`；默认每页 20，可选 50/100，筛选变动回第一页。计数先于分页，稳定排序带唯一键；页码越界回有效页；零条无虚假页码，读取失败单独报错。

文章以正式文章和待审核修订的逻辑文档去重；同文档可同时显示“已发布”和“待审核”。专辑详情按阅读顺序分页管理章节、README、类型扩展及导航；版本历史按文档分页。活动报名与核销从活动专辑进入。用户查询使用站主专用聚合，不逐页扫描全部 Auth 用户。概览指标单独加载，不阻塞其他列表。

### 配置与机器出口

- `/admin/settings` 保存首页五块、商业配置与署名；`/admin/card` 保存身份联系；`/admin/ai` 保存 AI 连接、分身指令与开关，管理完整知识库及验收；`/admin/avatar` 兼容跳转。密钥不回显，同一目标留空保留现值；改变目标须填写对应 Key。
- AI 连接检查就地反馈；知识库按准备、任务选择、建立、确认启用、使用与更新五步组织。生成完成后直接呈现站主确认，不以诊断分数限制；可选诊断区可在启用前后使用，允许 1–100 题、自动草稿与人工核对来源，无分组控件或最低配比。错配高亮，保留正确的失败问题；编辑或采纳仅变更独立草稿，不调整向量、检索规则或原报告。取消编辑有修改时确认放弃，未结束的草稿阻止会丢失草稿的切换。调用费用按出题、检索、回答分别确认；回答默认匿名视角。日常同步完成后由站主确认切换，不强制回归。重新进入只读进度，历史报告保留原题与原结果，不自动恢复付费调用。
- `/admin/orders` 保留服务履约含义；`/admin/payments` 是收款追踪，没有手工支付、退款或授予权益旁路。
- `/card.json` 与 `/llms.txt` 使用公开投影、缓存和 ETag，读取失败返回 503 / no-store；手册保持 `content_offerings.type=series`，独立 Skill 为 `skills` 分组、`paid-skill` 访问枚举。

### 后台编辑与快捷栏

列表负责定位，复杂表单进入对象编辑页。工作台保存所属专辑与返回位置，失败保留编辑内容；保存冲突不覆盖，结果未知先查询。普通站内链接离开时提醒未保存修改，刷新/关闭提醒受浏览器限制；草稿可手动下载。

后台不显示分身。工作台匿名预览仍放右侧快捷栏：桌面 ≥1280 时为非模态，窄屏模态抽屉，Escape 关闭并恢复触发点焦点。主题切换不重置表单。

### Web 导入与审核

`/admin/import?series={slug}` 是站主文件目录。手册 / 活动及旧技能章节兼容入口显示文件夹上传，博客显示已保存文件及修订。根目录选择为「导入文件夹中的内容」/「保留最外层文件夹」。差异区展示数量；每行左为相对路径、右为变更状态，「查看差异」在右侧栏并排展示云端原文与导入原文。确认后先附件后文档依次保存，每项独立显示结果并可重试；不删除云端缺失文件。空态为尚无保存文件，错误保留当前本地文件。

云端清单按文件顺序显示，每行左为路径与修订 / 发布状态、右为上移 / 下移 / 审核操作。点击审核在右侧栏自动加载站主可见的完整原文和匿名预览，底部吸附操作栏提供「编辑此修订 / 确认发布此修订」；确认发布更新线上文章。选中行高亮（沿用后台清单约定）；窄屏右栏退化为模态抽屉（既有后台快捷栏基建）；长路径换行。列表只读取文件及修订元数据。

`/admin/content` 保存待发布修订后提供审核发布；图片上传区下为附件库，点击图片在当前光标位置插入。外部图片使用独立表单（HTTPS URL + 替代文本）。上传不自动追加正文，匹配已有缺图引用时补齐该引用。目录导入不要求本地工具。

### 收件箱公开稿审核

站主收件箱显示待审与已公开会话；原始用户问题 / 分身答复位于私有展开区。公开问题与答复首次为空，只回填已发布的公开稿；发布需二者非空且勾选去个人信息 / 受限正文确认。可更新或撤回公开稿，隐藏操作不要求填写公开字段。撤回后原始记录保留。


### 个人中心生成额度

`/me` 的用量显示为 UTC 今日生成余量，包含有效预留及已派发尝试，排除 released / 过期预留。读取失败显示“配额暂不可用”；站主显示日额度不限、站级月限额仍适用。未来生效的订阅不提前提高当前额度。没有新增路由或组件。

### 独立 Skill 与 Obsidian 连接

- `/skills`：按介绍文章查询，服务端搜索、分页；新 Skill 不依赖系列记录。未转换旧技能保留入口。
- `/skills/[slug]`：公开介绍、登录／购买、授权下载与安装说明；无有效包不售卖，未授权不返回包文件清单。旧 `?article=` 保留原章节阅读。
- `/skills/[slug]` 的下载、购买、登录与安装说明在专属右栏；在线能力开启时显示“切换成在线测试”和地球图标，在线模式以电脑图标返回下载安装；切换仅改变当前右栏，不替换介绍正文或刷新页面。手机通过底部 SKILL 入口展开，不占用正文区域。
- 在线模式在右栏内显示 Skill、用途、输入指引、文本能力边界及对话，共用分身的消息／输入布局，但不共用会话或权限。模式、主题与抽屉切换保留输入和当前对话；失败保留输入并提供只读查询状态，不自动重试生成。URL 仅保存面板模式和会话 ID，不保存问题。`/skills/[slug]/chat` 兼容转到介绍页的在线模式，刷新后可读取本人已有对话。
- `/admin/skills`：逻辑文档列表包含仅有待审修订的介绍；介绍编辑复用工作台。`/admin/skills/[id]` 分步管理上传、当前版本、价格与在线使用，历史版本只读。
- `/admin/handbooks/connect`：创建、列出、撤销手册专用凭据；明文仅创建时显示。插件使用原生 Obsidian 设置和预览。“我的本地手册”按条目展开左右文稿列表、正文对照、进度与恢复；连接和线上状态静默恢复，进度更新不重建整页。所有上传均为草稿，成功后链接 `/admin/collections/[id]` 配置并发布，插件不提供权限、价格或发布操作。缺少 README 可经勾选创建空白介绍；覆盖需逐项确认，线上独有内容保留。
- `/collections` 及详情跳转 `/handbooks` 并保留合法章节参数。

专辑详情 `/admin/collections/[id]` 提供统一设置表单与“待发布更新”：一次保存展示、价格和导航；所选修订集中预览后整批发布。首次可选择 README 并同时上架，更新不自动改变生命周期。插件只指向此页面，不承担发布职责。
